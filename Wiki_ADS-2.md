## Активная задача: управляемый анализ в LibreChat

### Запрос

При запуске периодического расследования Kimi показывает пользователю `Мысли`, видит лишние инструменты ClickHouse и Grafana, вручную запускает низкоуровневые Map-шаги и не отображает ожидаемый прогресс расследования.

### Подтвержденное решение

- Архитектурный контракт находится в `/Users/subbotaevgenij/Desktop/ADS/Доки/ADS архитектура MapReduce.docx`.
- Нужный исходный код: репозиторий `Pendalf-Grey/Agentic-Data-Stack`, ветка `ads/ads2-mapreduce-architecture`, commit `fe8da41`.
- Для широкого анализа Kimi должен видеть только `ads-log-workflow` и `grafana`, а анализ запускать ровно одним `run_log_analysis`. ClickHouse MCP не входит в `modelSpecs.kimi-k2.6-ads`.
- Workflow скрывает `create_log_investigation`, очередь Map, `run_log_map_step` и Reduce внутри сервера. Внешне доступны только `run_log_analysis`, `get_log_analysis_status`, `get_log_analysis_results`.
- Дашборд строится единственным `create_grafana_dashboard_from_analysis(investigation_id)`.
- `KIMI_THINKING_TYPE=disabled` передается Moonshot в `addParams.thinking.type`; это техническое отключение reasoning, а не инструкция в prompt.
- LibreChat собирается из закрепленного образа и содержит патчи отмены MCP-вызовов.

### Задача: границы Map-входа и параллельность

Запрос: один сжатый вход, передаваемый в Map/`aiGenerate`, должен представлять не более 5000 исходных строк; одновременно workflow запускает 8 асинхронных Map-воркеров.

Подход: каждый воркер получает ровно один виртуальный Map-вход за шаг. Базовые compressed-батчи не пересобираются: при enqueue workflow делит RLE-серии только батчей запрошенного периода на фрагменты `<=5000` исходных строк и хранит их во внутренней `analytics.llm_map_inputs`. Очередь распределяет эти фрагменты по `batch_no mod 8`; `aiGenerate` получает JSON только соответствующего фрагмента.

2026-09-10, восстановление: в локальной raw-таблице нет исходных строк, хотя прежние сжатые батчи содержали 477174763 строки. Универсальный raw-компрессор нельзя применять к этому набору: его `--truncate` очистил только производную таблицу и вернул 0 батчей. Найден потоковый precompressed-источник `/Users/subbotaevgenij/PycharmProjects/Base/compressed_based.json`; до восстановления рабочего набора проверяется также прежний Docker volume. Приоритет source в скриптах исправлен: `LOGS_SOURCE_NAME`, затем `ADS_LLM_LOG_SOURCE_NAME`, затем Elasticsearch default.
2026-09-10, фактический объём после восстановления: `analytics.es_raw_logs` содержит 90 872 623 исходные строки. Физический размер таблицы на диске ClickHouse -- 7 363 226 460 байт (6,86 GiB); JSON-колонка `document_json` занимает 100 543 110 102 байта (93,64 GiB) до сжатия и 6 782 077 079 байт после сжатия. Проверять текущий размер через `system.parts` и `system.parts_columns`, а не по исторической записи о пустой таблице.
2026-09-10, семантическое сжатие: `analytics.es_log_compressed_batches` содержит 1 878 RLE-батчей, представляющих те же 90 872 623 исходные строки. Полезная нагрузка сократилась с 99 831 755 362 до 473 018 717 символов (211,05x); таблица занимает 76 021 884 байта на диске (72,50 MiB). Не путать это с колоночным сжатием ClickHouse: 7,36 GB -- физический объём raw-таблицы после сжатия СУБД, а 473 MB -- объём семантически сжатого JSON до колоночного сжатия.
2026-09-10, уточнение пользователя: ограничение 5000 относится к данным, передаваемым одному `aiGenerate`, а не к глобальной пересборке хранилища. Принято точечное решение: виртуальные Map-фрагменты создаются только для текущего расследования; полный rebatch не применяется.
2026-09-10, результат: для тестового расследования `codex-map-input-5000-20220501-03` за 01--03.05.2022 workflow создал 18 виртуальных Map-входов на 89705 строк. В ClickHouse подтверждено `max(rows_read)=5000` и `countIf(rows_read > 5000)=0`; входы распределены по всем восьми индексам воркеров. Очередь теста отменена без вызовов LLM, рабочий `mcp-log-workflow` перезапущен с этой реализацией.
2026-09-10, очистка: после подтверждения восстановления удалены временные recovery-контейнеры `ads2-recovery-librechat-clickhouse`, `ads2-recovery-clickhouse` и volumes `ads2_recovery_librechat_clickhouse`, `ads2_recovery_agentic_clickhouse`. Рабочие volumes ADS-2 и исходный `librechat_clickhouse_data` не затрагивались.

### Задача: читаемый дашборд Grafana

Запрос: заменить нечитабельный технический дашборд расследования визуальным представлением проблем, их серьезности, динамики и действий.

Подход: установлен и закреплен `volkovlabs-echarts-panel` версии `6.5.0`, совместимый с используемой Grafana `11.3.0`. Генератор дашбордов строит компактные KPI, вывод расследования, горизонтальные столбцы затронутых сервисов, кольцевое распределение серьезности, часовую суммарную динамику, действия и таблицу фактов. Источник визуализаций -- `analytics.llm_map_results`, поэтому он работает и с виртуальными Map-входами <=5000 строк.

2026-09-10, диагностика: пустые canvas Business Charts не были проблемой ClickHouse -- статичный график также не отображался. В сериализованном `getOption` кольцевой диаграммы Python-последовательность `\\n` превратилась в реальный перенос внутри JavaScript-строки `'{b}\n{d}%'`, и плагин получал `SyntaxError: Invalid or unexpected token`. Решение: экранировать обратный слеш в Python-строке и проверять JSON панели через живой Grafana перед публикацией. Полная схема options плагина (`editorMode`, `themeEditor`, `map`, `visualEditor`) задается явно для воспроизводимой работы при сохранении дашборда.

2026-09-10, результат: в браузере подтверждены реальные столбцы и кольцевая диаграмма без JavaScript-ошибок; шкала времени агрегирует события по часу, а таблица фактов расширена. Дашборд: http://localhost:3001/d/ads2-log-investigation-33f3846835c9/ads-2-log-analysis-log-investigation-33f3846835c9. `mcp-grafana` перезапущен и healthy, поэтому следующая генерация из LibreChat использует тот же шаблон.
2026-09-10, локализация: все поясняющие строки Map и обоих уровней Reduce должны формироваться на русском (кириллица); идентификаторы сервисов, метрик, кодов ошибок, SQL и JSON-ключи не переводятся. Это закреплено в Map prompt и Reduce instruction. Для уже завершенного расследования сохранен русскоязычный итог Reduce без повторного Map-анализа; русифицированы название, легенды, серьёзность и заголовки таблицы Grafana. Исторические английские Map-симптомы нормализуются в русские сервисные формулировки только на отображении, а будущие Map-результаты будут приходить на русском.
2026-09-10, confidence: показатель был свободной самооценкой Reduce LLM без формальной методики и мог неверно трактоваться как измеренная точность. Решение: исключить ключ `confidence` из контракта и prompt обоих уровней Reduce, удалить карточку из Grafana, а при выдаче старых результатов удалять ключ программно. Для текущего расследования поле также удалено из сохраненного JSON.
